# olpest — поверхность

Один репозиторий, два способа публикации:

- **GitHub Pages** — сейчас, без сервера;
- **VPS рядом с Omad** — позже, когда сервер будет готов. Файлы для него уже лежат здесь, Pages их не публикует.

```
olpest/
├── site/                         сам сайт — только эта папка уходит на Pages
│   ├── index.html
│   ├── favicon.svg, og.png
│   └── assets/                   app.js, style.css, three.js, шрифты
├── .github/workflows/pages.yml   автодеплой site/ на GitHub Pages
│
├── Dockerfile, Caddyfile, docker-compose.yml   ┐
├── deploy.ps1                                  │ для VPS рядом с Omad
└── deploy/                                     ┘ (см. раздел ниже)
```

## GitHub Pages

### 1. Создать репозиторий и залить код

На github.com: **New repository** → имя, например `olpest` → **Public** (на бесплатном плане Pages работает только для публичных репозиториев) → без README.

В папке проекта:

```bash
git init
git add .
git commit -m "olpest: этюд 03"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/olpest.git
git push -u origin main
```

### 2. Включить Pages (один раз)

Репозиторий → **Settings → Pages → Build and deployment → Source: GitHub Actions**.

После этого откройте вкладку **Actions**. Workflow «Pages» запустится сам при следующем push, или нажмите **Run workflow** вручную. Через минуту сайт будет на:

```
https://ВАШ_ЛОГИН.github.io/olpest/
```

Если назвать репозиторий `ВАШ_ЛОГИН.github.io`, сайт откроется прямо на `https://ВАШ_ЛОГИН.github.io/`.

### 3. Обновления

Любой `git push` в `main` заново выкладывает сайт. Ссылки на `app.js` и `style.css` содержат версию (`?v=4`). При заметных изменениях увеличивайте её в `site/index.html`, чтобы браузеры не держали старую копию: Pages кеширует файлы на 10 минут.

### 4. Свой домен (необязательно)

1. **Settings → Pages → Custom domain** → впишите домен → **Save**.
2. В DNS у регистратора:

   | Тип   | Имя   | Значение |
   |-------|-------|----------|
   | A     | `@`   | 185.199.108.153 |
   | A     | `@`   | 185.199.109.153 |
   | A     | `@`   | 185.199.110.153 |
   | A     | `@`   | 185.199.111.153 |
   | CNAME | `www` | `ВАШ_ЛОГИН.github.io` (без имени репозитория) |

   По желанию добавьте AAAA для `@`: `2606:50c0:8000::153`, `2606:50c0:8001::153`, `2606:50c0:8002::153`, `2606:50c0:8003::153`.
3. Когда DNS обновится, включите **Enforce HTTPS** на той же странице.
4. Рекомендуется подтвердить домен в настройках аккаунта: **Settings → Pages → Add a domain**. Так никто другой не сможет привязать его к своему Pages.

Файл `CNAME` в репозитории не нужен: при деплое через Actions GitHub берёт домен из настроек. Адрес в превью-тегах (`og:url`, `og:image`) workflow подставит сам: домен, если он задан, иначе адрес Pages.

Когда VPS будет готов, достаточно перевести DNS домена на сервер: см. раздел ниже.

### Чем Pages отличается от VPS

- Заголовки сервера на Pages задать нельзя, поэтому Content-Security-Policy стоит в `<meta>` прямо в `index.html`.
- Кеш у Pages фиксированный, 10 минут. Отсюда версии `?v=` в ссылках.

### Посмотреть локально

```bash
cd site
python3 -m http.server 8080
# http://localhost:8080
```

## VPS рядом с Omad (позже)

Сайт живёт в `/opt/olpest`, в своём контейнере `olpest-web`, **без портов 80/443**: их держит Caddy от Omad. Он видит контейнер через общую Docker-сеть `edge` и проксирует на него домен. Лимиты: 96 МБ памяти и половина ядра.

**Не выкладывайте, пока тот, кто ведёт Omad, не даст добро.** Порядок:

1. Бэкап базы Omad (`backup.sh`) — на стороне Omad.
2. DNS домена → `186.246.3.210` (A-записи `@` и `www`).
3. `.\deploy.ps1 -Server root@186.246.3.210 -Domain ваш-домен.ru`. Скрипт создаст сеть `edge`, если её нет, разложит файлы в `/opt/olpest`, соберёт и запустит контейнер и проверит его. Снаружи сайт пока не виден, и это нормально.
4. Omad добавляет блок домена в свой `Caddyfile` и подключает Caddy к сети `edge` (`deploy/omad-caddy-snippet.txt`), затем выкладывает Omad как обычно.
5. Проверить `https://ваш-домен.ru`.

Если PowerShell запрещает скрипты: `powershell -ExecutionPolicy Bypass -File .\deploy.ps1 -Server ... -Domain ...`.

- Обновить: снова `deploy.ps1`. Прошлая версия сохраняется как образ `olpest-web:prev`, и при сбое скрипт откатывается на неё сам.
- Откатить вручную: `ssh root@186.246.3.210 "bash /opt/olpest/deploy/rollback.sh"`.
- Логи: `ssh root@186.246.3.210 "docker logs --tail 50 olpest-web"`.

Скрипты никогда не открывают порты 80/443, не ставят веб-серверы на хост, не трогают `/opt/omad` и контейнеры Omad и не делают глобальных `prune` и `down`.
